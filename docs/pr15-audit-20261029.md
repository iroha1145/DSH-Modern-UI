# 2026-10-29 PR #15 审计意见复核

对象：外部审计《DSH-Modern-UI 全方位深度审计报告：PR #15、插件剩余 Bug 与全量构建版特性迁移对比》（针对 PR #15 HEAD `e30eaf0`）。复核方法与 [10-28 复核](audit-20261028.md) 相同：旧补丁（`patches/dsh-ui.patch`，应用到 upstream `22ddee37`）打满后的源码树、实际运行的官方 rc.4 编译产物和插件源码三方对照，结论以 rc.4 产物为准。安装器各条用真实的 `current.json` 只读调用新代码核对；会话数据层各条在实际构建出的包上做实验；样式各条在无界面 Chrome 里用编译后的样式表量。

## 总体判断

- 审计说对、本次已修的：运行状态行样式表（UI-1）、官方描边按钮常态边线（UI-2）、菜单两个条件底色被覆盖层压掉（UI-3 的实质部分）、7 个无回退别名（UI-5）、1017 徽章截断（UI-8）、定时任务外层卡片圆角（UI-9）、升级时误换 profile（PR15-2）、macOS 上的测试路径（PR15-8）、`install-existing.sh` 读到版本变量（PR15-7 第 3 点）、展示增量重算的死判断（PR15-5），以及第三部分的插件管理页、设置分节、终端滚动条和文件树「其它」条目。
- 提交归属不对：PR15-4、PR15-5、PR15-6 说的行为来自 main 上的 PR #12（`9b570fa`）和 PR #13（`254dcd5`），不是 PR #15 引入的。PR #15 对插件源码只改了 6 个文件。
- 行号和数字多处对不上：`manager.mjs` 只有 443 行；补丁是 50,190 行，不是 54,327 行；第三部分标题写 16 项，实际列了 15 项。下文不沿用审计的行号。

## 逐条结论：PR #15

| 条目 | 结论 | 本次处理 |
| --- | --- | --- |
| PR15-1 宿主版本锁死 | 部分属实。复用已有官方包时，用户原地升级官方包会让启动校验失败；独立安装换宿主版本会被拒绝；`uninstall` 后 `recovery.json` 仍记着原宿主。这些都是有意的保护：插件只对记录的宿主版本验证过，数据目录也不能降级 | 行为不改。报错写明记录的版本和实际找到的版本，并给出两条出路：装回记录的版本，或者换新程序目录、配一份隔离的数据副本。启动校验失败时附同样的提示。[旧版宿主兼容](backward-compatibility.md) 补了说明 |
| PR15-2 `--from-profile` 换掉已托管的 profile | 部分属实。这一行 main 上就有，但 PR #15 的入口脚本第一次把参数暴露出来 | 已修：程序目录已托管某个 profile 时，再传不同的 `--from-profile` 直接拒绝，检查在备份之前 |
| PR15-3 `compactAnswer` 没接到界面 | 部分属实。它是官方公开契约字段，插件计算并对外提供，合同测试断言与官方投影器一致；插件自己的界面不读它。折叠后回答上方 12px 与补丁版完全相同，16px 是 rc.4 才加的。「插入消息后仍为 true」不成立：按定义，输入在回答之后就该是 true，官方同样 | 不改，保持补丁版间距 |
| PR15-4 回答识别四种误判 | (1) 不看 settled：数据层属实，界面看不到，运行中的回合不折叠，回合结束后才按规则折叠。(2) 正文和最后一次工具调用在同一步：属实，是 [回答折叠复核](answer-fold-audit-20261029.md) 已记录的已知限制。(3) 「全部回复」模式下旁白可见：设计如此。(4) 两处收尾步定义不一致：不属实 | 不改 |
| PR15-5 展示增量重算的判断 | 部分属实。判断比较同一个键的步骤号，永远为假。官方 rc.4 原样如此，但官方的派生只读步骤号，所以无害；PR #12/#13 之后插件的派生还读步骤内容，流式期间增量结果会与全量重建不同。界面上看不到：回合还开着时没人读这两个字段，步骤收尾和回合结束都会触发重算 | 已修：改为比较派生实际用到的两个事实，即是否收尾回复、是否有可见思考。在构建包上逐阶段对比，增量结果等于全量重建 |
| PR15-6 截断窗口里首步思考不能折叠 | 不属实。已结束回合的答案锚点就是最终消息的 seq，思考分组随回合整组隐藏，不依赖过程起点。另外发现一个相关的新问题：窗口里没有 `turn/start`、答案步是第一个过程证据、答案之后还有工具步骤时，过程起点退到答案之后，答案后的旁白在「仅最终回答」下没有折叠。只在回合超过 500 条消息、窗口恰好从答案步切开时出现 | 已修新问题：过程起点不晚于答案。过程都在答案之前时，结果与官方相同 |
| PR15-7 旧宿主的三点 | (1) rc.2/rc.3 只放行验证过的平台：刻意如此。(2) bootstrap 先建目录、先下载 Node 再校验：顺序属实，但 Node 压缩包在退出时就被清掉，「约 45MB 残留」不属实，最后只剩一个空的程序目录。(3) `install-existing.sh` 两条分支对版本变量处理不一致：属实，影响小 | (3) 已修：复用已有官方包时，入口脚本不再读 `DSH_MODERN_BACKEND_VERSION`。(1)(2) 不改 |
| PR15-8 macOS 上测试失败 | 属实。macOS 的临时目录在 `/var`，实际路径在 `/private/var`。CI 只跑 Linux 和 Windows，所以一直没发现 | 已修：测试先取临时目录的实际路径 |
| PR15-9 `.JqwYuG_panelHeader` 在 rc.2/rc.3 不存在 | 不属实。审计扫的是 `dsh-web-app` 包，这个类在文档预览包里，rc.2、rc.3、rc.4 三个版本都有 | 不改 |
