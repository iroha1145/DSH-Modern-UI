# 2026-10-26 独立复审修复

本轮处理独立复审的 N01、N02、N03，并纠正联网状态持久化说明。发行仍基于固定的官方源码与完整补丁；没有引入新的会话格式，也没有迁移用户的活跃数据。

## 修复范围

| 条目 | 发行行为 | 检查方式 |
| --- | --- | --- |
| N01 | 私有 Node.js 与次级脚本运行环境统一为 24.22.1；五个平台的次级下载摘要同步更新。 | 官方安全版本及摘要核对；实际私有启动器报告版本与 Brotli 修复常量；冻结依赖中的原生加载器实际加载；正常、损坏压缩响应及后续恢复。 |
| N02 | 安装器在保存配置、备份和替换源码前检查真实目录关系。安装目录内仅允许 `data` 子树，独立外部数据目录继续可用。 | 源码、运行时、备份、旧源码及路径别名拒绝；符号链接、Windows 目录联接、大小写及 Unicode 等价名称；正常升级与失败重试保持原会话字节。 |
| N03 | 异步保存推理档位时，当前焦点作为该组唯一停点；Tab 与 Shift+Tab 正常离开该组，其他菜单控件的循环规则不变。 | 实际组件的保存中与完成态正反导航对照，并保留手机及平板模型列表先进入搜索框的浏览器断言。 |

Node.js 官方的 [2026 年 10 月安全公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)与 [24.22.1 发布说明](https://nodejs.org/en/blog/release/v24.22.1)确认该版本包含 CVE-2026-111497 的修复。本轮使用无害的本地压缩响应核对真实抓取路径，没有尝试利用漏洞。运行环境的版本与二进制校验独立于 npm 生产依赖扫描。

目录检查优先使用既有目录的真实身份。尚不存在的路径只有在关系无法只读判断时，才使用同一文件系统中的独占临时目录核对名称规则；探测失败时停止安装并清理。已经确定分离的既有父目录不会要求共同祖先可写。非法的历史安装配置也会被拒绝，原数据不会为通过检查而自动迁移。

连续强制安装使用各自唯一的旧源码目录，避免同一秒内重名而将旧树嵌套或覆盖。Windows 运行环境验证在独立的 PowerShell 进程中完成，父进程等待退出并释放进程对象后再改名；目录共享冲突仍有有限重试，权限拒绝立即失败。验证进程本身不新增超时承诺。

联网兼容说明已明确：成功的 `/web` 命令结算可能先形成可恢复的关闭选择，随后才在获准的步骤开始前写入 `web/search`。因此，没有该事件不代表新版仍启用联网；旧读取方在此窗口可能接受日志，却不能遵循新版选择。回退仍应使用停止写入后取得的备份。

## 验证入口

```sh
node --test tests/release.test.mjs
python3 tests/installers.py
bash tests/posix-prepare.sh
node scripts/verify-release.mjs --applied-source <还原源码目录>
```

`posix-prepare.sh` 在独立临时安装中实际下载私有 Node、恢复缺失的 npm 文件、强制重新准备源码，再经真实启动器核对版本、数据目录和参数。启动器探针使用只输出进程信息的临时应用入口，完整应用的构建与配置导出另由源码检查执行。`runtime-loader.mjs` 从还原源码的冻结依赖锁读取原生加载器版本，在测试目录安装并实际调用它。Windows 的 `tests/windows-prepare.ps1` 执行对应准备、恢复、目录联接与启动器检查，持续集成分别使用 PowerShell 5.1 和 PowerShell 7。

还原源码的检查覆盖完整构建、宿主与客户端类型、界面测试、运行环境和网络回归、文档同步及 Chromium/WebKit 中的模型选择器。推理档位新增八项组件用例：最终用例在原实现上四项失败、四项对照通过，修复后该包 303 项通过。浏览器断言和已有界面基准没有因本轮修改而放宽。

导出的完整补丁还应用到重新下载且校验通过的官方压缩包；逐文件比较内容、符号链接和可执行权限，并检查已删除文件不存在。具体自动检查结果以合并请求对应提交的持续集成为准。

## 验证边界

本轮不宣称全部上游浏览器用例通过，不调用付费模型或真实用户会话。默认浏览器发行与可选 Electron 桌面包分开验收；既有 extract-zip、node-forge 和 Electron 告警仍见[上一轮范围说明](audit-remediation.md#依赖处理)。生产依赖扫描无告警不能替代这些交付物的检查。
