# 前端动画、加载与手机布局优化验收（2026-11-12）

基线为 main 的 `0bb32e8`（0.1.17）。本次修复侧栏收缩中途换树/跳变、默认分组仅显示五个会话造成的空白，并将非首屏渲染依赖拆分、把 Modern 代码高亮移到专用 Worker。服务仍使用原官方 Host 和原鉴权，只在隔离的 localhost 环境验收，没有新增公网入口。

## 实现与取舍

- 侧栏和 AppFrame 跟随实际 CSS transition 的完成或取消收尾，保留同一棵内容树和展开内容尺寸；快速反转、拖动和视口改变不再依赖估算的超时。
- 会话分组根据真实容器和行高补足可用空间。已有手动分页、焦点、搜索和折叠祖先语义保留；缩小视口时不自动移除已显示的行。20 / 2,000 会话夹具在桌面、长手机和短手机视口验证填充及有限挂载，触摸行高为 44 px。
- 运行中切换“减少动画”会停止行重排、标题跑马灯、聊天折叠和滚动跟随，并提交实际终态。正在阅读历史的用户不会被强制拉到底部。
- OpenUI、KaTeX、语法数据及高亮 Worker 经官方 `require.async` 加载，CSS 复用 Cordis owner 生命周期。原文/TeX 立即可读；确认的加载失败提供用户主动重试，不自动换实现或重试。
- 高亮保留现有 60 语言、别名、Go grammar 修正、tokenizer、长行和工作量预算。Worker 负责计算，取消、视图状态及 DOM 留在主线程；卸载终止 Worker、撤销 Blob、清空语法状态，延迟到达的加载结果不能生成孤立 Worker。
- **32 行上限限定于流式 frame 和异步行 chunk**，包括有色 tail。已完成的小代码块仍沿用受 80 行、4,096 字符和工作量预算限制的整块 HTML 路径。120 短行流式场景先显示 80 行着色和 40 行原文，下一次更新或结束流式后补齐；不新增后台追赶循环。
- 复用官方模块传输、共享 React/Cordis、现有高亮算法和动画生命周期，没有引入通用动画框架、主线程 Worker 回退或修改官方模块表。
- 稳定 Lightning CSS 导出映射的键顺序，避免样式未变却产生新分块哈希。连续两次完整构建的 92 个 JS 文件逐字节一致；独立检查 117 个文件、131 个 CSS module 导入，消费端均按名称取值，不依赖键顺序。

## 整页实测

Windows、Edge 157.0.4341.46、Node 24.18.0；未修改的官方 DSH 0.2.1-rc.4 HTTP Host、隔离本地确定性模型和空欢迎页。两版均冻结构建，每轮交替先后顺序。冷启动使用新浏览器上下文，重复加载立即复用同一上下文；认证和欢迎步骤先完成，不计入导航。网络为无节流 loopback，不代表互联网或慢 Wi-Fi。

桌面为 1280×800、CPU×1；手机模拟为 390×844、触摸、CPU×4。可输入时间是编辑器可见并有有效几何尺寸后的第二个动画帧；每次继续观察 1.5 秒记录启动后台任务。指标包含整个 Host 的全部资源，而不仅是 Modern 包。每组 20 次，共 160 次导航，不剔除异常值；中位数和 P95 按 nearest-rank 计算，20 次中的 P95 取排序第 19 项。

| 可输入时间（ms） | 基线中位数 | 优化中位数 | 变化 | P95：基线 → 优化 |
| --- | ---: | ---: | ---: | ---: |
| 桌面 · 冷启动 | 1,057 | 862 | -18.5% | 1,270 → 1,040 |
| 桌面 · 重复加载 | 614 | 521 | -15.2% | 776 → 708 |
| 手机视口 / CPU×4 · 冷启动 | 5,005 | 4,129 | -17.5% | 5,661 → 4,742 |
| 手机视口 / CPU×4 · 重复加载 | 2,938 | 2,462 | -16.2% | 3,621 → 2,926 |

桌面冷启动整个 Host 资源传输中位数为 7,080,685 → 5,890,351 B（-16.8%）。重复加载主要复用缓存，不应将首包压缩率直接套成重复加载的下载或时间收益。原始数据保留每次 FCP、LCP、CLS、long task、资源字节和 CDP 指标。

## 首次代码高亮的成本与输入响应

以下为专用 loopback 夹具的**单次冷样本**，使用真实 React、CodeBlock、Shiki Worker 和官方脚本传输；只把无关 Host primitives 的 pointerModality 查询替换为外部种子，以隔离 Modern 的新增成本。这不是整页统计，也不是“整个 Host 没有长任务”的结论。每个样本的六次输入都发生在 Worker 尚未完成时。

| 配置 | 原文显示 ms | 完成着色 ms | 最大主线程长任务 ms | 最大 rAF 间隔 ms | 输入延迟 / 下一帧最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| CPU×1 | 10.3 | 137.6 | 0 | 13.1 | 0.3 / 6.9 |
| CPU×4 | 72.4 | 333.0 | 0 | 78.1 | 1.6 / 8.2 |

静态枚举项目客户端的 transition、keyframes、WAAPI、rAF、动画 timer 和 reduced-motion 入口，覆盖布局/导航、弹层、控件反馈、会话过程、输入/欢迎页、状态/内容及公共 motion token。结合重点代码审阅和已有回归，不能等同于所有动画在所有真实设备和状态组合中逐项播放。

最终冻结包的 Edge 157、Firefox 157、Windows WebKit 27.2 各 6 项整页检查通过（18/18）：侧栏填充和收放、按需公式/Python、窄视口设置、短屏输入和抽屉。Edge/WebKit 另各 5 项触摸模拟通过（10/10），包含 44 px 目标、会话搜索、模型菜单、390/320 px 设置和 390×320 长草稿。主代理亲自操作实际 Chrome 页面并查看最终截图，检查桌面/手机、代码和表格、设置、侧栏终态；此前还检查深色、OpenUI 交互与文件/Markdown 侧栏。

实查未发现新增错位或不可达内容；宽表格使用自身横向滚动，长草稿使用输入区内部滚动，长会话名使用省略，不能把这些既定行为当作裁切缺陷。

## 已知边界

- Firefox 157 的 Playwright 触摸注入在 `display:contents` 文本上只产生 pointerdown/up、不产生 click，原生无 React 最小页可复现。保留原失败证据，没有把 tap 改成 click；Firefox 仅声明视口及 Worker 验证，真实触屏仍未证实。[Playwright 对应实现](https://raw.githubusercontent.com/microsoft/playwright/v1.64.1/browser_patches/firefox/juggler/content/PageAgent.js)。
- Windows headless WebKit 的原生 backdrop-filter 对照在负 z、直接滤镜和 z=0 三种形式均不呈现可见模糊，而 Edge 正常。故没有针对该环境添加材质绕行；不据此推断真实 Safari 的显示。
- 原始 0.1.17 的 root owner 热更新也可出现空白，刷新恢复；本次未加入 root fallback。构建更新后刷新页面，沿用现有安装/架构约定。
- 未验证真实 Android/iOS 键盘、动态浏览器栏、物理触屏 Firefox、真实 Safari/macOS 材质、多显示器、高刷新率、原生 Electron 多窗口或全部辅助技术。Windows/macOS 样式标记的浏览器测试不等于原生系统验收；Blob Worker 的 file:// 可运行也不等于完整 Electron 验收。
