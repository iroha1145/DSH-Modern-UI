# 2026-10-29 main 与 Markdown 加粗审计复核

对象：外部审计《DSH-Modern-UI 最新 main（40d2e14）前端深度审计与 Markdown `**` 加粗失效专项分析报告》。

复核方法：
- 把插件实际用的两套 Markdown 语法（流式时的 `parseGfm`、回复结束后的 `parseGfmWithMath`）单独打包，用审计举的例句和会话日志逐一对比修复前后：本机 59 份日志（含 `*` 的回复与思考块 554 个，含 `$` 的 313 个），服务器 70 份日志（含 `*` 的块 903 个，含 `$` 的 236 个）。
- 在临时实例里让假模型流式输出同样的句子，看真实页面上回复结束后的样子。
- 审计给的本机数字（结束瞬间丢 48 处加粗、72 个 `**` 被吞、12 个块前后不一致）都能复现。

## 总体判断

- 加粗失效的真实来源是审计的根因一和根因二，都已修。根因二第 3 点（中文标点后紧跟英文或数字不能闭合）本机日志里没有，服务器日志里却很常见，例如 `**研究对象：**DeepSeek`，随后在 PR #18 里一并修了。
- 根因三（全角星号 `＊`）在两边共 129 份日志里出现 0 次，没有证据，不改。
- 第二部分的「发现」标签重复、macOS 菜单透明度、注释引用已删测试三条属实，已修；另外两条维持 [PR #15 复核](pr15-audit-20261029.md) 的结论。

## 逐条结论

| 条目 | 结论 | 本次处理 |
| --- | --- | --- |
| 根因一 单美元 `$` 吞掉 `**` | 属实。回复结束后的语法用上游 `math()` 默认的单美元行内公式，没有任何边界规则，`$115.36亿` 会和同一段里下一个 `$` 配成公式，中间的 `**` 被吞进去；流式语法不带公式，所以回复一结束加粗就掉，`从 $5 涨到 $8` 这类价格也被排成公式字体 | 已修：上游只保留 `$$`，单美元改由 `mathCompatibility.ts` 按 Pandoc 规则判断：开头的 `$` 后面不能是空白，结尾的 `$` 前面不能是空白、后面不能紧跟数字。另照 TeX 的做法，开头之后第一个未转义的 `$` 就是结尾，它不能结尾就整个不算公式，所以「价格 $5，…在 $x$」不会把中间的文字吞掉 |
| 根因二 缺 CJK 开启规则与反向错位加粗 | 属实。`提出**“引力 = 熵力”**假说` 这种「汉字后紧跟 `**`、再接标点」的开头，CommonMark 的规则不让它开启；同一段有两处时，会把中间的「而且」加粗 | 已修：加了与已有闭合规则对称的开启规则，`**` 前是 CJK 字符、后是标点就能开启 |
| 根因二第 3 点 标点后紧跟英文或数字不能闭合 | 属实。本机日志里没有，服务器日志里常见：`**研究对象：**DeepSeek`、`**CED：**40 层`、`**异步重叠。**ZOS` | PR #18 已修：`**` 挨着中文标点、另一侧是字母或数字时也能开启或闭合。只认中文标点（中日韩符号区、全角符号区和中文弯引号），英文用的是 ASCII 标点，所以 `**Note.**Next` 这类英文仍按 CommonMark 处理 |
| 根因三 全角星号 `＊` | 本机与服务器共 129 份日志里出现 0 次；按 CommonMark 全角 `＊＊` 本来就不是强调 | 不改，没有证据时不另造语法 |
| 根因四第 1 点 `attentionMarkers` | 属实。插件这份照抄的是旧版 micromark，现行上游已经把 `*` 和 `_` 排除在这条捷径外 | 已改为与上游一致，影响只在 `**_` 这类罕见边界 |
| 根因四第 2 点 `$**\text{D}**$` | 不是缺陷，外层是合法公式，`**` 在公式里就是乘号 | 不改 |
| 2.1 提交复核表 | 对个别提交的描述不准，例如 bc32986 并不涉及 `--host-version`，不影响结论 | 无 |
| 2.2 插件管理页两个「发现」 | 属实，启用实验插件市场包时出现，本机与服务器都有 | 已修：官方插件市场界面不渲染任何子槽，README 只能靠遮挡整个标签显示，所以遮挡保留；标签栏里重复的那一行由 `official-surfaces.css` 藏起，见 [普通问题的代码折叠与列表槽遮挡的限制](presentation-parity.md) |
| 2.3 macOS 菜单在减少透明度时仍半透明 | 属实，只影响 macOS 桌面外壳，网页版不写 `data-platform` | 已修：三个回退块里同时让 `--dsw-specific-menu` 跟随 `--dsw-menu-surface-fill` |
| 2.4 第 1 条 回答折叠启发式 | 维持 PR #15 复核 PR15-4 的结论 | 不改 |
| 2.4 第 2 条 侧栏收起残影 | 维持 PR #15 复核 UI-6 的结论，全量构建版本来如此 | 不改 |
