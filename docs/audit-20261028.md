# 2026-10-28 插件化审计意见复核

对象：外部审计《DSH-Modern-UI 插件化迁移全面审计报告》（针对 main `64c2c00`）。复核方法：把旧补丁（`patches/dsh-ui.patch`，应用到 upstream `22ddee37` 的 rc.3 源码）打满后的源码树、未打补丁的源码树、实际运行的官方 rc.4 编译产物（`@deepseek-ai/dsh@0.2.1-rc.4` 的 `lib/client.js`）和插件源码四方对照；每条结论都以 rc.4 产物为准，不以 rc.3 源码推断。审计引用的补丁行号全部对不上（它写补丁有 14,009 行，实际 50,190 行），下文不沿用它的行号。

## 总体判断

- 审计说对的部分：若干官方包仍渲染未打补丁的样式、运行状态行在推理阶段只剩秒数、手机端 `overscroll-behavior-y` 丢了、`modern.conversation.input.model.label` 没有任何登记、模型设置页的「按模型声明推理强度」没有迁移。
- 审计说错的部分：终端变量别名「没定义」（早已定义，只是作用域不对）、`message.code` 槽改名伤第三方（rc.4 根本没有这个槽）、插件市场/插件管理详情页的代码块折叠（rc.4 里没有那两个组件）、`UserMessageBubble`/`Menu`/`Tooltip` 退回官方样式（前者 rc.4 已不存在，后两者补丁没改）、`--bui-*` 一类令牌名（补丁里不存在）、B6 里若干「丢失圆角阴影」（多数只差 2px 或已由主题映射等价）。
- 审计的核心建议「停用官方 `ui-chat`/`ui-model` 由插件整体接管」不可按原样执行：rc.4 没有 `ui-model` 包（叫 `ui-model-selection`，停用它会让插件依赖的 `modelDirectories` 服务消失，整个展示层不启动）；停用 `ui-chat` 要连会话数据层（`conversation-nodes`，22 文件 4,754 行）、`chat` 视图目标、`useChat` 钩子、ChatView/ChatFlow/分组座、四个节点视图、两个工厂、额度浮层、三条设置行和 `ui-chat` 配置命名空间一起接管，约 80 个文件、一万两千行，且 rc.4 只有编译产物没有 source map。这是一个独立项目，不在本次修复内。
- 「让官方包加载插件 primitives」在设计上被封死：官方 Web 外壳把 primitives 作为冻结的静态模块表交给加载器（`dsh-client-modules` README 明确写了不可替换），`docs/plugin-ui-map.md` 也明文拒绝模块表劫持。

## 覆盖官方界面样式的约束

`official-surfaces.css`、`official-chat-view.css` 只碰官方包仍在渲染的界面，优先用 `data-*`/`role`/`aria` 钩子，万不得已才用 `[class*="_局部名"]` 子串（官方编译类名形如 `_3e4SsG_menu`，哈希随内容变，整名不可依赖）；特异度压过官方同属性规则而不用 `!important`；颜色只用主题令牌；动画带 `prefers-reduced-motion` 关闭；不加任何彩色侧边条。官方升级后要重新核对这两份文件里注释标出的钩子与类名。
